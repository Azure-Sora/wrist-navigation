# 后台同步、唤醒与耗电（0.3.3）

同步由 Android 通知事件驱动，活动导航附加心跳。蓝牙传输由运动健康 / XMS 完成；本应用没有独立 GPS 定位、路线请求或额外蓝牙扫描循环。

| 状态 | 通知读取与发送 | CPU 唤醒锁 |
| --- | --- | --- |
| 空闲 / 已结束 / 暂停 | 无周期读取；同内容不重复发送，依靠通知或连接事件 | 不持有 |
| 活动导航 | 通知更新后350ms去抖；变化发送最小间隔500ms；不变内容约8秒心跳并补读通知 | 有效导航且节点就绪时持有 |
| 暂时读取失败 | 监听仍连接且同步启用时60秒重试 | 释放 |
| 监听断开 | 清除读取定时任务，等待系统重绑定 | 释放 |
| 手环断连但高德仍导航 | 活动通知补读仍可运行；查询连接至少间隔10秒，依赖刷新/SDK事件触发 | 释放 |

## 锁屏保活

`NavigationSyncService` 是 connectedDevice 前台服务。同步启用时空闲也保留服务与互联监听；这不是零开销，但不等于空闲持有 CPU 锁。本应用的通知显示可以关闭，前台服务仍然存在。

活动且连接时使用 PARTIAL_WAKE_LOCK：每次 acquire 的超时为60秒，后续状态刷新距离上次续期至少30秒时续租。因此正常导航中锁基本连续持有，**不是每8秒短暂唤醒一次**。它防止 CPU 休眠，不点亮手机屏幕，也不代表 CPU 一直满负荷。每次判断还要求通知检查距今不足20秒。

结束、暂停、断连、监听失效或服务销毁时释放。若刷新异常停止，最多等本次60秒租期到期。当前方案优先保留已验证的锁屏同步；相较允许 CPU 深睡会有额外耗电，但没有测得每小时增量，不能用瞬时CPU接近0%代替电量测试。

## 自动打开与结束

- 新导航调用 launchWearApp，成功后本次导航不重复打开；失败最多3次，间隔至少5秒，请求10秒超时。
- 通知发布/移除先350ms去抖。原状态active且高德通知全部消失时，再等待1.5秒复核后发送ended，避免通知替换导致误退出。时间阈值是启发式判断。
- 手环本次页面已收到active，随后收到ended，且导航页可见、设置未打开时，释放常亮并调用$app.exit()。空闲、过期、断连不当作结束。
- 开机或覆盖更新后尝试恢复已保存的同步启用状态，受系统后台限制影响，真实重启恢复尚未验证。

## 省电边界与验证

不用时关闭应用内同步开关，可停止本应用前台服务并释放锁；关闭通知显示本身不是省电措施。手环常亮开关影响手环屏幕，不会关闭手机 CPU 唤醒锁。

用户已确认当前功能正常，前序确认自动打开、亮屏/锁屏同步、隐藏通知有效。没有进行无充电条件下的固定时长对照测试；高德定位导航和运动健康自身耗电也需与本应用增量区分。后续可用同设备、同路线和相近屏幕条件，对比只运行高德与开启腕上同步各30–60分钟，再决定是否调整保活策略。本版不改变已验证的保活行为。
